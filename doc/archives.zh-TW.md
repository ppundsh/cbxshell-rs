# 壓縮檔與圖檔封裝支援 (Archives)

CBX Shell 原生支援多種常見漫畫與圖檔壓縮封裝格式，具備完整的編碼相容性與檔名解析能力。（EPUB、MOBI、IBA、AZW、PDF 等電子書格式請參閱 [電子書封面擷取支援](./ebooks.zh-TW.md)。）

---

## 1. 支援容器格式

- **ZIP / CBZ**：支援標準 ZIP（含 ZIP64）、Deflate、Deflate64、LZMA；加密項目（含 AES）因無密碼而直接略過，不會嘗試解密。
- **RAR / CBR**：以純 Rust 解碼器支援 RAR4 與 RAR5；加密標頭或加密項目略過，分卷項目不處理。
- **7z / CB7**：支援 LZMA、LZMA2、PPMd、BZip2、Deflate、LZ4（固實與非固實皆可）；解析前先驗證簽章檔頭。
- **TAR / CBT**：標準 TAR 封裝。

---

## 2. 多語系 CJK 檔名編碼辨識 (Multi-byte CJK Decoding)

針對早期壓縮軟體或特定平台（如 DLsite、日文作品）產生的未標記 UTF-8 flag 之 ZIP 封裝，由於未設定 UTF-8 旗標時，一般解壓工具常預設套用 DOS CP437 代碼頁，導致繁體中文（Big5）、簡體中文（GBK）及日文（Shift-JIS / CP932）出現亂碼。

系統直接讀取檔名之原始位元組切片（Raw Bytes），透過 Windows 編碼解析 API 依序驗證與轉換：
1. 優先檢查是否符合合法 UTF-8 格式。
2. 若非 UTF-8，自動依序嘗試 CP932（Shift-JIS）、系統原生 ANSI 代碼頁、CP950（Big5）與 CP936（GBK）。
3. 使中文、日文假名與漢字正確呈現，減少編碼亂碼問題。

---

## 3. 封面選取與圖檔處理演算法

- **自然排序（Natural Sorting）**：依據 Windows 檔案總管邏輯進行檔名排序（例如 `1.jpg` 在 `10.jpg` 之前）。
- **優先使用連續檔名的第一個檔案**：啟用後（`prefer_continuous_sequence`，預設開啟），系統會依 `(資料夾深度, 資料夾名稱)` 與檔名數字骨架（將連續數字正規化為 `#`，例如 `page_01.jpg` -> `page_#.jpg`）將圖檔分組；優先選取最淺層資料夾中張數最多（至少 2 張）的連續編號序列，並取該序列自然排序後的第一個檔案作為封面，避免雜項說明圖或零填充異常檔名（如 `0000_info.jpg`）搶佔主序列封面。
- **長條圖檔自動裁切（Tall Strip Cropping）**：當圖檔長寬比超過 3:1（如長條漫畫/條漫）時，自動擷取上方 2:3 區域以維持縮圖比例。
- **純色與簡單圖片過濾**：自動跳過版權聲明、空白頁或純色圖檔，尋找後續有效封面。
- **縮圖外框樣式**：提供 6 種樣式（無外框、無外框圓弧、底片卷軸、柔和陰影、相框風格、書籍封面），可依媒體類別分別設定。
- **無封面壓縮檔中立處理**：
  若壓縮檔內未包含圖檔，系統回傳 `E_FAIL` 並維持 Windows 系統預設壓縮檔圖示，運作日誌中客觀標記為「無封面圖檔」（正常完成），避免被判定為錯誤。

---

## 4. 部分讀取：只讀需要的位元組

縮圖不需要整個壓縮檔。各格式只讀取「找出封面」與「解出封面」所需的部分，因此網路共用資料夾、雲端預留位置檔或尚未傳輸完成的大檔，只會傳輸少量位元組：

| 格式 | 讀取內容 | 說明 |
|---|---|---|
| **ZIP / CBZ** | 檔尾（≤ 64 KiB）→ 中央目錄 → 封面項目 | 中央目錄位於檔尾，選定封面後直接跳到該項目的本地標頭與資料。其他項目的資料完全不讀。 |
| **RAR / CBR** | 逐一讀取區塊標頭（以 seek 跳過資料）→ 封面項目 | 每個項目前方都有自我描述的標頭；以 4 KiB 視窗讀標頭、驗證標頭 CRC 後直接跳過資料區。未啟用自然排序時，找到第一張可用圖檔就停止；啟用時只走完標頭。接著僅讀取「簽章＋主標頭＋封面所屬區塊」組成小型壓縮檔交給解碼器。**固實**項目需從所屬固實群組的開頭讀到封面資料結尾（固實串流無法從中間解碼）。 |
| **7z / CB7** | 簽章檔頭（32 B）→ 檔尾標頭 → 封面所在資料區塊 | 標頭位於檔尾；解碼時依序處理資料區塊，固實區塊需從區塊開頭解起（受 128 MiB 累計上限與逾時限制）。 |
| **TAR / CBT** | 逐一讀取 512 B 標頭（以 seek 跳過資料）→ 封面項目 | 第一輪只走標頭並記錄每個候選的資料位置；選定後再 seek 到該位置讀取封面。 |

**壓縮檔處理逾時**：在「壓縮檔」分頁設定（預設 30 秒，可設 5–120 秒）。它同時限制掃描封面的時間，以及外掛處理壓縮檔縮圖請求的總時間（另加 5 秒供解碼與縮放）；影片等其他格式仍使用影片分頁的「單檔處理時間上限」。

RAR 的快速路徑在遇到少見結構（例如加密標頭、非標準 SFX）或解碼器不接受精簡壓縮檔時，會自動退回舊的「讀取前綴（16–96 MiB）再解析」方式，因此相容性不變。

> 開頭仍需要可讀取：ZIP 與 7z 的目錄在檔尾，必須能 seek 到檔尾；RAR 與 TAR 的標頭散佈在整個檔案，需要能 seek 到各標頭位置。若檔案仍在下載或複製中而尚未包含封面所在位置，縮圖會失敗，待檔案完整後重新產生即可。
